## 1. 本轮解决的问题

本轮没有删除模型的证据边界，而是重新组织其显示层级：

- **主预测页**只聚焦序列、任务进度、预测数值、单位、训练样本数、开发集 OOF 指标和端点条件。
- 不再在每一个端点卡片上重复显示“低置信度”“仅供科研”“未独立验证”。
- 主结果表不再重复设置“验证状态”和“信心标记”两列。
- 主预测页只保留一条中性的“网站与结果说明”入口。
- **独立的“网站与结果说明”页**集中解释证据等级、使用范围、验证阶段、端点训练量、OOF、条件合同与表示限制。
- 原始 JSON 和下载文件中的 `research_only`、`low_confidence`、`validation_status`、`insufficient_validation` 与 `warnings` 均未删除或改写。
- 新增浏览器隔离的**历史任务页**，可以查看过去提交的批次、序列和执行结果，并恢复完整预测面板。

这种设计兼顾两件事：第一眼不让警示文字淹没计算结果；需要审计时又能完整追溯证据边界。

## 2. 三个概念的区别

### 2.1 低置信度

这是**结果可靠性维度**。它表示某个端点的训练证据或模型稳定性相对不足，常见原因包括：

- 训练样本或唯一序列过少；
- 标签来自弱规则、正样本-未标注构造或来源定义的二分类；
- 物种、实验介质、浓度、时间、给药途径等条件异质；
- 分组 OOF 指标较弱或不稳定；
- 裸序列无法编码会显著影响端点的真实修饰结构。

它回答的是“这个数值目前有多可靠”，不是“是否允许使用”。

### 2.2 仅供科研

这是**使用范围维度**。它表示结果当前适用于方法研究、候选排序、数据探索与实验假设生成，不用于临床、给药、安全性定论或自动实验决策。

它回答的是“这个结果允许被用于什么”，不等价于“模型分数一定很差”。即使某个端点的开发集 OOF 很高，在治理和独立验证完成前仍可保持仅供科研。

### 2.3 未独立验证

这是**评估阶段维度**。当前模型已有分组 OOF 开发评估，但没有真正独立于训练开发过程的外部来源、独立实验队列或封存测试集验证。

它回答的是“当前成绩在哪个评估阶段”。它不表示模型完全无用，而表示现有 OOF 可能高估真实泛化能力，尚不能把开发指标当成外部性能保证。

### 2.4 为什么三者不能合并

| 维度 | 对应标记 | 回答的问题 |
|---|---|---|
| 可靠性 | 低置信度 | 这个端点的当前证据和稳定性如何？ |
| 用途 | 仅供科研 | 允许把结果用于哪些决策？ |
| 评估阶段 | 未独立验证 | 是否已在真正独立数据上证明泛化？ |

三者彼此正交。本轮只是把它们从主结果页移到专门说明页，没有在底层结果中删除。

## 3. 当前四个页面

### ① 序列输入

- 单条裸序列；
- 每行一条多序列；
- “名称 + Tab + 序列”；
- 多记录 FASTA；
- FA/FAA/FASTA/TXT/CSV/TSV 文件；
- 每批最多 32 条有效序列，文件最大 1 MB；
- 提交后自动跳转到预测面板。

### ② 预测面板

- 右上角实时任务进展；
- 批次任务表；
- 已完成序列选择器；
- 每条序列的 18 端点卡片；
- 当前序列完整结果表；
- 分类/排序图；
- 批量汇总表；
- 原始 JSON；
- JSON/TSV/ZIP 下载；
- “查看历史任务”和“查看网站与结果说明”入口。

### ③ 历史任务

历史页按批次显示：

- 批次编号、提交时间、完成时间；
- 有效、完成、失败和拒绝序列数；
- 总预测数值数；
- 序列名称摘要；
- 所选批次的任务编号、序列名称、标准序列、来源、状态和端点数；
- 点击“打开预测结果”后恢复该批次的任务表、序列选择器、18 端点、图表、原始 JSON 和下载文件，并自动回到预测面板。

### ④ 网站与结果说明

- 集中解释低置信度、仅供科研与未独立验证；
- 展示 18 个端点的训练样本数、开发集 OOF、证据通道、特征路由、信心标记、使用范围、验证阶段和条件合同；
- 解释分类分数、正样本-未标注排序分数和跨端点比较限制；
- 解释裸序列对环化、D-AA、二硫键、封端、脂化和 PEG 化的表示限制。

## 4. 历史任务的存储和隔离合同

### 4.1 存储位置

```text
.omx/web_history/v31/
  <sha256(browser_owner)[:32]>/
    <batch_id>.json
```

每个文件保存完整 `batch_state`，包括批次、提交序列、任务状态和各序列的可审计预测对象。

### 4.2 浏览器隔离

- 首次打开页面时生成随机浏览器标识；
- 标识通过 Gradio `BrowserState` 保存在当前浏览器的本地存储；
- 服务器只使用标识的 SHA-256 截断值作为目录名，原始标识不写入文件名；
- 页面不存在全局历史列表，浏览器 A 不能通过正常网页操作列出或加载浏览器 B 的批次；
- 单元测试已覆盖跨 owner 列表/加载隔离与非法批次编号拒绝。

### 4.3 持久化、保留和限制

- 每个浏览器最多保留最近 50 个批次；
- 保存使用临时文件加 `os.replace` 原子替换；
- 本机 `127.0.0.1:7860` 的浏览器标识可跨服务重启保留；
- Gradio 临时公网 URL 每次重建可能改变域名，浏览器本地存储按域名隔离，因此新公网 URL 不会自动继承旧 URL 的浏览器标识；旧历史文件仍在本机磁盘，但新临时域名不能自动关联；
- 这是临时科研站的**浏览器级隔离**，不是账号系统或企业级访问控制；持有本机文件系统权限的人员仍可读取历史文件；
- 公网站无登录认证，不应提交敏感、保密或未公开序列。
